The problem

An agent’s guardrails live in its prompt.

  • Autonomous agents run shell, open files, call the network — on your machine, with your credentials.
  • A prompt injection in an issue, a web page, or a dependency can talk the agent into anything.
  • The agent can also lie about what it did. Its logs are written by the thing you don’t trust.
  • Every sponsor here secures a layer above the agent. Nothing watches what it actually does.
The idea

Enforce the boundary in the kernel — below where the agent can argue.

A policy written in a prompt is a suggestion.
A policy enforced at the LSM hook is physics.

Built with yeet — eBPF programs loaded and driven from JavaScript.

Architecture · three layers

One agent, one job description, enforced three ways.

1 · The boundary

BPF LSM hooks on file_open, socket_connect, exec. A guarded cgroup may touch only its workspace and the broker. Everything else is refused with EPERM and the process is killed before the access.

2 · The credential

The agent holds only placeholder keys. A localhost broker swaps in the real key only for in-scope calls. A leaked placeholder is worthless.

3 · The record

Every kernel decision streams into ClickHouse. Incidents, attack timelines and fleet stats, queried live. The agent can’t edit this log.

The guard · ~30 lines, loaded by yeet

The whole boundary is a BPF LSM program.

SEC("lsm/file_open")
int BPF_PROG(guard_open, struct file *file, int ret) {
    if (ret) return ret;
    u64 cg; u32 *mode = guarded_mode(&cg);      // is this agent guarded?
    if (!mode) return 0;
    if (!is_protected(file)) return 0;         // ~/.ssh, ~/.aws, .env ...
    emit(cg, KIND_OPEN, DENY);                   // -> ring buffer -> ClickHouse
    bpf_send_signal(SIGKILL);                   // kill before the read
    return -EPERM;
}
